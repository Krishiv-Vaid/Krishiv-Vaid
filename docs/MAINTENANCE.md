# How this profile is built

Everything visible in the README is generated by code in this repository.
GitHub sanitises README HTML (no scripts, no CSS), so the design ships as
self-contained SVGs plus one animated, lossless pixel-art WebP. Each SVG embeds a subset of
JetBrains Mono and pins every line with `textLength`, so columns stay aligned
even if the font fails to load.

```
profilegen/            library
  theme.py             colour tokens for dark + light (single source of truth)
  svg.py               escaping, font subsetting, monospace text runs
  ascii_art.py         photo -> character portrait
  hero.py              portrait + fastfetch panel (wide and compact layouts)
  static_assets.py     section rules, project cards, badges, toolkit, beyond tiles
  github_data.py       GraphQL collection, retries, cached fallback
  palette.py           muted language colours and shade ramps
  koi/evolution.py     contributions -> age class, length, ornament
  koi/pond.py          pixel-art pond: rim, water, pads, bridge, koi, ripples
  koi/animate.py       route/pattern seeds, exact-palette GIF
  stats.py             live statistics panel
  pipeline.py          glue, change detection
scripts/               command-line entry points (one per asset family)
tests/                 pytest suite (geometry, physics, data handling, SVG validity)
config.toml            data-driven inputs: login, window, exclusions, pond size
source/                portrait cutout (greyscale + alpha) and its ASCII output
assets/                committed static SVGs
docs/img/              previews: koi age classes, portrait variants
```

## Setup

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
```

## Regenerating assets

| what | command | committed to |
|--|--|--|
| hero portrait | `python scripts/generate_portrait.py [--variants]` | `assets/portrait-*.svg` |
| cards, badges, toolkit, tiles, section rules | `python scripts/generate_static.py` | `assets/` |
| koi age-class previews | `python scripts/generate_koi.py --stages docs/img/koi-stages.png` | `docs/img/` |
| GitHub data, koi pond, stats | see the workflow below | `output` branch |

Run the dynamic pipeline locally:

```bash
export GITHUB_TOKEN=$(gh auth token)
python scripts/collect_github.py --out out/snapshot.json
python scripts/generate_koi.py --snapshot out/snapshot.json --out out
python scripts/generate_stats.py --snapshot out/snapshot.json --koi out/koi.json --out out
```

Try other inputs without touching GitHub:

```bash
python scripts/generate_koi.py --contributions 1800 \
  --languages "C++:#f34b7d:0.55,Python:#3572A5:0.30,TypeScript:#3178c6:0.15" --out /tmp/pond
```

### Portrait

`source/portrait-cutout.png` is a greyscale + alpha crop of the profile photo.
The background was removed with BiRefNet (via `rembg`). To start from a new photo:

```bash
pip install -r requirements-portrait.txt
python scripts/generate_portrait.py --from-photo path/to/photo.jpg --crop x0,y0,x1,y1 --variants
```

The pipeline:

1. resamples the cutout onto the exact character grid. Cells are 0.6 em wide
   and 1.2 em tall, so rows = cols × (h / w) / 2 and the face isn't stretched;
2. sets tone levels from the face region only, so black hair and a black shirt
   don't flatten the skin tones;
3. blends 30% whole-subject levels back in, so the hair keeps some texture;
4. adds Sobel edges and a light local-contrast boost;
   cells on the top-left edge of the silhouette get a steel-blue rim light;
5. matches every cell against glyph bitmaps rendered from the real font. Flat
   cells use a tone ramp; cells with internal structure pick the glyph whose
   strokes line up with the edge;
6. quantises each cell into six ink tones per theme.

`docs/img/portrait-variants.png` compares the approaches that were tried. The
chosen parameters are `FINAL` in `scripts/generate_portrait.py`.

### Editing content

- Panel fields: `SECTIONS` in `profilegen/hero.py`.
- Project cards: `PROJECTS` in `profilegen/static_assets.py`.
- Badges, toolkit and "beyond the terminal" tiles: `BADGES`, `TOOLKIT` and `TILES` in the same file.

## The daily workflow

`.github/workflows/update-profile.yml` runs daily at 06:23 UTC, on manual
dispatch (*Actions → update profile → Run workflow*), and on pushes that change
the generators. It:

1. downloads the currently published `output` branch into `previous/`;
2. collects metrics with `GITHUB_TOKEN`. This uses two GraphQL queries,
   retries with backoff, and honours `Retry-After` and `X-RateLimit-Reset`;
3. falls back to `previous/snapshot.json`, marked stale, if GitHub is down;
   the panel then reads "cached <date>";
4. re-renders the koi pond only if its inputs hash changed. The hash covers
   the contribution count, the lily-pad colours, the day (the route is
   re-seeded daily), the pond config and the renderer's source;
5. renders the stats panel;
6. if any asset differs from what is published, force-pushes `out/` to
   `output` as a single orphan commit. `main` never receives bot commits, and
   binary churn never builds up in history.

### Metric definitions

| metric | scope |
|--|--|
| contributions | contribution calendar total over the rolling window (default 365 days). Includes private contributions as a bare count if the profile shows them |
| koi input | the calendar total minus commits to `exclude_repos` (default: this repo). Bot-authored commits are never attributed to the user, so they never count |
| commits | commit contributions in the window |
| pull requests | all-time authored PRs, any repository; merged count shown alongside |
| public repos / stars | owned, public, non-fork repositories |
| languages | bytes per language across those repositories, minus `exclude_repos` and markup languages (`exclude_languages`) |

`GITHUB_TOKEN` can read all public data. To make the numbers match the
profile exactly when private contributions are shown, add a fine-grained PAT
with no extra permissions as the repository secret `PROFILE_TOKEN`.

### Troubleshooting

- **The koi pond or stats image is broken.** Check that the `output` branch exists
  and the last workflow run passed. Run the workflow manually once after
  creating the repository.
- **The panel says "cached".** GitHub collection failed and the last good
  snapshot was reused. The run log has a warning with the cause.
- **Fonts look different.** SVGs embed their own font. If a viewer blocks
  embedded fonts, `textLength` still keeps alignment, using the fallback stack.

### The koi pond

- Scene: 210 x 106 native pixels, scaled 4x (WebP) or 3x (GIF) with
  nearest-neighbour sampling, so it displays 1:1 at 840 px and pixels stay square.
- Size: `length = 16 + 58 g` native pixels, with `g = min(1, (c / 2800)^0.45)`.
  It is strictly increasing in the contribution count.
- Movement: a closed random Fourier curve (re-seeded from `login:date`), traversed
  by arc length with a periodic speed wobble. The spine samples the path behind
  the head, plus a travelling wave with an integer number of beats per loop. Big
  fish get a smoother path so they never fold.
- Colours: seven lily pads assigned to languages by largest remainder; the koi's
  patches use the top language, spots (Nisai and up) the second.
- Encoding: lossless animated WebP (true alpha, a few hundred KB) and a GIF with
  an exact shared palette and a transparent index.
